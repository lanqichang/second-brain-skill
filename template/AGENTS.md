# 第二大脑 · 工作区宪法

> 所有 AI 进来都先读本文件，`CLAUDE.md` 指向它。这里只放三样：红线、落地位置、触发词。**具体怎么做一律写进 skill**（`知识库/skills/`）。
> 本文件上限 12KB，超了先移出一条再加一条。规则只维护这一份。

## 零、开工

- **先查有没有现成的 skill**。命中第五节触发词表，就先读对应 skill 再动手。没有现成 skill 的事，第一次做完只在经验总结里留一段做法，第二次用到再写成 skill。
- **写东西、对外表达、替我做决定之前，先读根目录 `SOUL.md`**，对齐我的声音和原则。
- **原因查清、修复实施、结果验证是三个状态**，不互相代替。最终结果验证通过才告诉我「完成」。
- 干完一件事，主动问一句：「这次要不要记一条经验？」

## 二、文件夹结构

```
第二大脑/
├── AGENTS.md / CLAUDE.md / SOUL.md / README.md   ← 根目录只放这四份
├── 收集箱/        别人的东西：链接、图片、摘录。先收，不整理
├── 灵感箱/        我自己的东西：想法、选题、以后也许会做的事
├── 项目区/{进行中,已完成,已归档}   在做的事，一个项目一个文件夹
├── 创作区/{未发布,已发布}         我写的东西
├── 学习思考区/    正在消化的学习输入，还没想清楚的
├── 生活区/        健康、家庭、孩子、旅行
└── 知识库/{经验总结,方法论,skills}   沉淀
```

知识库三层：`经验总结`（一手经验，允许矛盾）→ `方法论`（去个例、抽共性）→ `skills`（可执行）。**只能往上提炼，不能跳级**：没踩过坑就直接写方法论，写出来的是别人的话。

拿不准一份东西放哪，问三句：

1. 它还会天天改吗？会 → 项目区或创作区。
2. 它跟某件具体的事绑死吗？是 → 项目区。
3. 三个月后它对别的事还有用吗？有 → 知识库。

还是拿不准，放收集箱。不要为了归类卡住。

## 三、红线

### 原则（做事的底层规律）

1. **信任大于聪明**。移动、删除、重命名、大改之前先告诉我，不静默动我的东西。
2. **简约优先**。新规则、新文件夹、新自动化，必须由我本人碰到的具体麻烦驱动，不为「以后可能用到」而建。
3. **涌现式分类**。不预建子分类；同一类攒够 5 份、靠搜才找得到时，再建子文件夹。
4. **默认直接执行，不反复确认**。例外必须先问：删除或覆盖、发布到公开平台、付费、发消息给别人、其他不可逆操作、意图不明。
5. **替我省时间**。能核实的自己核实，能补充的自己补充，只把非我本人不可的判断留给我。
6. **引用外部材料必须可验证**。给出处和前后文，原文、推断、待核实分开标。核不到就不写。
7. **交成品**。替我写的东西不留占位符和「待确认」标记；缺细节先在库里找原始素材，找不到就换说法或删掉。
8. **评审不自评**。要评审就另开一个独立的 AI 会话来评，写的和评的不是同一个。
9. **完成任务附上成果位置**。文件给完整路径，网页给完整网址。
10. **相对日期一律换成绝对日期**。「上周三」写成具体的年月日。

### 禁止（坚决不能做）

11. **不在根目录新建文件或文件夹**，也不建「临时」「草稿」「杂项」这类文件夹。落地位置见第四节。
12. **同类经验永远追加进同一个文件**，不新建。
13. **不编造**。事实、数据、引语、出处，核不到就不写。
14. **不确定就问，别猜**。
15. （我自己的红线，往下续行）

## 四、落地位置

| 内容 | 位置 |
|---|---|
| 想法（「记录」） | `灵感箱/YYYY-MM-DD-<短标题>.md` |
| 链接、摘录、图片（「收藏」） | `收集箱/YYYY-MM-DD-<短标题>.<ext>` |
| 在写的文章、稿子、方案 | `创作区/未发布/<项目>/` |
| 发出去的成品 | `创作区/已发布/` |
| 项目 | `项目区/进行中/<项目>/` |
| 读书笔记、研究整理 | `学习思考区/` |
| 健康、家庭、生活事务 | `生活区/` |
| 经验（「总结」「复盘」） | `知识库/经验总结/<场景>经验总结.md`，场景不确定就问我 |
| 可复用的做法 | `知识库/skills/<skill名字>.md` |

**命名**：`<说的是哪件事 + 文档类型> <MMDD>`，日期放末尾，例如 `客户异议处理话术 0817.md`。不用「草稿」「反馈」「最终版」这类看不出内容的标题。三个例外：经验总结和 skill 不带日期（一直在改）；灵感箱和收集箱日期放最前（按时间排）。

## 五、触发词（我说这个词，你就做这件事）

| 我说 | 你做 |
|---|---|
| 记录 | 存进 `灵感箱/`，文件名 `YYYY-MM-DD-<短标题>.md`，回显我的原话 |
| 收藏、保存链接 | 存进 `收集箱/` |
| 总结、复盘 | 按第六节格式，追加到 `知识库/经验总结/<场景>经验总结.md` |
| 写成 skill | 复制 `知识库/skills/Skill六格模板.md`，逐格问我填，写完在本表加一行 |
| 生成 SOUL | 读 `创作区/已发布/` 和我指定的文字，按 `SOUL.md` 里的框架填写 |
| 整理一下 | 列出收集箱和灵感箱里超过 30 天的文件，逐类建议去向，等我点头再动 |

**加触发词不用问我，直接在表里加一行。** 这张表越用越长。

## 六、经验总结怎么写

我说「总结」「复盘」，按这个格式**追加**到对应场景文件末尾：

```markdown
## <一句话说清这次的教训> · YYYY-MM-DD

**当时在干什么**：（一句话背景）

**发生了什么**：（具体到细节）

**教训**：（下次遇到同样的情况，第一步该做什么）

**下次的动作**：（一句可执行的话）
```

三条要求：具体比正确重要（写出日期和数字）；允许和旧记录矛盾；只追加，不覆盖。

## 七、写一个 skill

一个 skill 就是把「我每次都要教你的那套」一次写好，永久复用。六格：触发场景、输入、步骤、输出标准、不要什么、代表案例。模板和范例都在 `知识库/skills/`。

什么时候该写：同一类事做过 3 次，能写出明确步骤和完成标准，换一个 AI 照着做结果不走样。
